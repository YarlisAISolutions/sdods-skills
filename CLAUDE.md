# CLAUDE.md: sdods-skills

## What this repository is

The public distribution of the SDODS agent integration: Agent Skills, the five SDODS subagents, the
SDODS MCP server registration, slash commands and a SessionStart hook. Together they form one Claude
Code / GitHub Copilot CLI plugin marketplace. SDODS is BDD test automation for UI, API and hybrid
flows (https://sdods.com).

Who uses it:

- People using Claude Code or Copilot CLI who add the plugin marketplace at
  https://sdods.com/skills.git. That URL redirects to this repository through the hosting rewrites
  in sdods `firebase.json`.
- Any agent (Codex, Cursor, Gemini CLI and others) that installs the skills through the `skills` npx tool.
- `@sdods/cli`, whose skills install subcommand ships the same skills, built from the same sources.
  The README lists the exact install commands.

**Every file here is generated.** The generator is `scripts/build-agent-plugin.ts` in the SDODS
monorepo (github.com/YarlisAISolutions/sdods). To change a skill, agent, hook or manifest, change its
source in sdods, not here. A direct edit is overwritten on the next release.

## Layout

| Path | What it is |
| --- | --- |
| `.claude-plugin/marketplace.json` | Marketplace `sdods` with one plugin, `sdods`, at `./plugins/sdods`. Its version is the SDODS release. |
| `plugins/sdods/` | The plugin: `.claude-plugin/plugin.json`, `.mcp.json` (runs `npx -y @sdods/cli mcp`), `agents/`, `skills/`, `hooks/`. |
| `plugins/sdods/agents/` | `sdods-{planner,generator,healer,upgrader,reviewer}.md`, built from `ROLE_PROMPTS` and `CONVENTIONS` in `@sdods/mcp`. |
| `plugins/sdods/skills/` | The skills under short names (`run`, `record`, ...) plus the slash commands (`/sdods:generate`, `/sdods:heal`, ...), all marked `metadata.internal: true`. |
| `plugins/sdods/hooks/` | `hooks.json` and `session-start.mjs`. The hook prints a workspace orientation, reads only the local filesystem and runs in Claude Code only. |
| `skills/` | Top-level Agent Skills (`sdods`, `sdods-record`, `sdods-run`, `sdods-start-ui`) for `npx skills add`. Copied from `packages/cli/skills` in sdods. |
| `README.md` | Install guide. Generated by the `readme()` function in the build script. |
| `LICENSE` | Apache-2.0, copied from sdods. |
| `CLAUDE.md`, `AGENTS.md` | This guide. `AGENTS.md` is `@CLAUDE.md`, so Codex and other agents read the same file. They are the only hand-written files. |

The repository has no `.github/` directory, no CI, no package manifest and no tags.

## Setup

Nothing to install or build. Verification needs:

- the `claude` CLI (Claude Code), for `claude plugin validate`
- Node.js, for `node --check`
- `jq`

## Verify

Run this from the repository root before you finish any change. It must exit 0:

```bash
claude plugin validate . && claude plugin validate plugins/sdods && node --check plugins/sdods/hooks/session-start.mjs && jq empty plugins/sdods/.mcp.json plugins/sdods/hooks/hooks.json
```

- `claude plugin validate .` checks the marketplace manifest.
- `claude plugin validate plugins/sdods` checks the plugin manifest and its components. One warning is
  expected: `ICON_MISSING`, because the plugin ships no icon. Fix that in sdods, not here.
- `node --check` makes sure the session hook parses.
- `jq empty` makes sure the MCP and hook JSON files parse.

`claude plugin validate` may print sandbox notes about blocked telemetry hosts. They do not change the
result.

Loading the plugin into a live Claude Code session (the `--plugin-dir` flag) needs an interactive
session and network access, so it is not part of verify.

## Conventions

- **Releases.** The sdods release workflow (`.github/workflows/release.yml`, in the job that runs when
  `SKILLS_REPO_TOKEN` is set) runs the `plugin:build` package script. It then runs
  `scripts/push-agent-plugin.mjs`, which writes one commit, authored by `SDODS <admin@sdods.com>` and
  titled `sdods <version>`, straight to `main` through the GitHub Git Data API. That is the only way
  content reaches `main` here. The version in `marketplace.json` and `plugin.json` always equals the
  `@sdods/cli` version.
- **Agent and manual changes.** Work on a branch (`feat/<key>-...` or `fix/<key>-...` for a YCadence
  item) and open a PR. Never push to `main`.
- **Commits.** Use a Conventional Commit subject (`docs: ...`, `fix: ...`). For a YCadence item, add a
  `Resolves <KEY>` footer. The repository uses no DCO and no `Signed-off-by`.
- **Publishing.** Users install from https://sdods.com/skills.git and from `@sdods/cli` on npm. Nothing
  here is published separately. Homebrew and Scoop packages come from `homebrew-sdods` and `scoop-sdods`,
  not from this repository.

## Do not touch

- **Any generated file** (everything except `CLAUDE.md` and `AGENTS.md`). The next release overwrites
  it. Make the change in sdods (`scripts/build-agent-plugin.ts`, `packages/cli/skills`, `plugin/`,
  `packages/mcp`) and let the release publish it.
- **`CLAUDE.md` and `AGENTS.md` during a release.** `push-agent-plugin.mjs` replaces the whole tree, so
  the next release deletes these two files unless the build script emits them. Until it does, check
  after each release that they are still here.
- **`metadata.internal: true`** in `plugins/sdods/skills/*/SKILL.md`. It keeps the plugin's own copies
  out of `npx skills` discovery, so users don't see every skill twice.
- **The MCP server key `sdods` in `.mcp.json`.** Agent `tools:` lines use `mcp__plugin_sdods_sdods__*`, so
  renaming the server, plugin or marketplace breaks every subagent and every install command.
- **The hook's local-only behaviour.** `session-start.mjs` makes no network calls and starts no
  processes, and it does nothing outside an SDODS workspace. Users trust it on every session start.
- **Secrets.** There are none, and the plugin needs none. Never add keys, tokens or `.env` files. The
  release token `SKILLS_REPO_TOKEN` lives in the sdods repository's secrets.
- **The owner name in user-facing text.** The README uses `sdods.com/skills.git` on purpose, so no
  README names the GitHub owner.
